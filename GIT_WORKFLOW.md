# Отправка изменений без ручной загрузки файлов

Рабочая папка на Mac: `/Users/roman/Documents/Codex/test/flight-time-calculator`.
Репозиторий: `https://github.com/Fatym9999/flight-time-calculator`.

## Обычный порядок работы

1. Работать только в ветке `dev`.
2. Перед изменениями проверить `git status --short --branch`. Если нет местных изменений, получить обновления через `git pull --ff-only`.
3. Внести изменения и выполнить подходящие проверки.
4. Посмотреть `git diff` и выбрать только файлы текущей задачи через `git add <пути файлов>`. Не добавлять автоматически всё содержимое папки.
5. Проверить `git diff --cached`, создать коммит с понятным описанием и выполнить `git push origin dev`.
6. Дождаться успешного запуска GitHub Actions и проверить `https://dev.moonhaze.ru`.
7. Пользователь сам создаёт Pull Request из `dev` в `main` и выполняет merge. Агент не изменяет `main` и не включает автоматическое слияние.

Редактирование файла и локальный коммит ещё не обновляют сайт. Обновление тестового сайта запускается после отправки коммита на GitHub.

## Что настроено на этом Mac

- Локальная ветка `dev` отслеживает `origin/dev`.
- Обычный `git push` направлен в `dev` этого репозитория.
- `git pull` допускает только перемотку вперёд: при расхождении истории он остановится, не создавая merge автоматически.
- Локальный обработчик `.git/hooks/pre-push` разрешает только отправку в `dev` исходного репозитория и запрещает её удаление. Это настройка данной рабочей копии; на другие компьютеры автоматически не переносится и не заменяет правила защиты веток на GitHub.
- `.gitignore` исключает служебные файлы macOS, Python, локальные `.env` и результаты сборки `dist`.
- Официальный GitHub CLI находится в `/Users/roman/Documents/Codex/test/.tools/github-cli/2.102.0/bin/gh`. Вход выполняется через браузер; пароли и токены не добавляются в репозиторий и не отправляются в чат.

Авторизация проверяется командой:

```sh
/Users/roman/Documents/Codex/test/.tools/github-cli/2.102.0/bin/gh auth status --hostname github.com
```

Проверки сборки и публикации описаны в `DEPLOYMENT.md`. В опубликованный сайт этот документ и локальные настройки Git не включаются.
