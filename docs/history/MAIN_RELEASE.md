# Предложение публикации основной версии

Статус: только подготовка файлов в тестовой ветке. Основная ветка, GitHub Pages и база не изменены.

Команда `python3 scripts/build-main-site.py` создаёт соседнюю папку `flight-time-main-publish` без архива.

## Поведение после публикации

- По существующей ссылке открывается единый калькулятор.
- Без входа используются существующие записи `flight-time-entries-v2`. Открытие страницы не переписывает и не очищает их.
- После входа загружается существующий журнал Supabase. Локальные записи не объединяются с ним автоматически; при выходе снова доступны локальные часы.
- Вход по коду, импорт/экспорт и синхронизация остаются. Убрана плашка «Тестовая версия».
- Supabase и SMTP остаются текущими: `flight-time-test` и Resend. Тестовый отправитель Resend допускает только почту владельца; вход других людей пока не готов.
- Основная и тестовая страницы используют одну облачную базу и одну сессию на общем домене GitHub Pages. До будущих экспериментов со схемой базы необходимо выделить отдельный тестовый проект; рабочий журнал не использовать для разрушающих проверок.

## После отдельного подтверждения владельца

Владелец загружает содержимое папки в **Fatym9999/flight-time-calculator**, сохраняя существующий адрес и настройки Pages. Проверить обновлённую страницу без входа, после входа и на телефоне; сравнить итог с резервным экспортом. Не менять домен: localStorage связан с доменом браузера. Ветка `main` не обновляется агентом без явного разрешения.

Старая версия остаётся в истории Git. При откате публикации облачные записи сохраняются в Supabase; старый калькулятор показывает локальный журнал.
