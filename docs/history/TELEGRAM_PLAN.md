# План входа через Telegram

Дата исследования: 8 октября 2026. Работа — в `test/experiments`. Основной сайт обновляется владельцем только после проверки и отдельного решения о публикации.

## Решение

Использовать официальный Telegram Login через OpenID Connect (OIDC), подключённый как `custom:telegram` в Supabase Auth. Бот представляет калькулятор при подтверждении входа. Обмен кодов и проверку токенов выполняет Supabase: отдельный постоянно работающий обработчик бота для этой схемы не нужен. Это вывод из поддерживаемого обеими платформами OIDC-потока, который необходимо подтвердить настоящим тестом. [Telegram Login](https://core.telegram.org/bots/telegram-login), [Supabase custom providers](https://supabase.com/docs/guides/auth/custom-oauth-providers).

По решению владельца первую версию делаем без объединения с почтовым аккаунтом: первый вход через Telegram создаёт отдельный аккаунт с пустым журналом. Налёт переносится пользователем через существующий импорт JSON. Вход по почте остаётся отдельным доступным вариантом. Связывание способов входа отложено.

## 2. Настроить Telegram и Supabase вручную

Владелец создаёт тестового бота в BotFather и открывает настройки Login Widget. Из них нужны Client ID и Client Secret. В Supabase создаётся OIDC-провайдер `custom:telegram` с issuer `https://oauth.telegram.org`, разрешениями `openid profile` и `email_optional: true`. Телефон и право отправки сообщений для входа не запрашиваем. Пользовательские провайдеры доступны на Free (до трёх). [Настройки Telegram](https://core.telegram.org/bots/telegram-login), [Настройки Supabase](https://supabase.com/docs/guides/auth/custom-oauth-providers).

Callback URL копируется из формы провайдера Supabase и добавляется в разрешённые URL Telegram. Отдельно в Supabase разрешается точный адрес возвращения на тестовый сайт, включая путь репозитория GitHub Pages. Client Secret хранится только в настройках Supabase; в HTML и Git его нет. [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls).

Перед оформлением проверить минимальный реальный вход. У Telegram нет отдельного UserInfo endpoint: подтвердить, что Supabase получает профиль из проверенного ID token. При несовместимости исследовать конкретную ошибку, не добавлять собственный сервер заранее.

## 3. Изменить код

- `auth-config.js`: независимые переключатели почты и Telegram, идентификатор провайдера, конфигурация тестового проекта.
- `auth-client.js`: создавать клиент независимо от включения почтового OTP; добавить `signInWithOAuth`, выбрать PKCE и контролируемую обработку возврата. Сейчас `detectSessionInUrl: false`, поэтому OAuth без изменения обработки не завершится.
- Новый `auth-callback.html` и скрипт: обмен кода через `exchangeCodeForSession`, проверка пользователя сервером, очистка параметров URL, переход в калькулятор; понятные ошибки и возможность начать заново. Код должен завершаться в том же браузере, где начат вход. [PKCE](https://supabase.com/docs/guides/auth/sessions/pkce-flow).
- `registration.html` и `registration.js`: кнопка «Войти через Telegram», сохранение формы почты, отображение аккаунтов без email по имени или понятной подписи. Убрать утверждение «Почта подтверждена» для Telegram.
- Проверить CSP для нового проекта и callback, пути к скриптам и включение новых файлов в комплект публикации. Схема журнала и правила доступа уже используют `user.id`, поэтому смена способа входа сама по себе не требует переписывать синхронизацию.

## 4. Проверки

Автоматически проверить запуск OAuth, успешный и ошибочный callback, отсутствие email, повторную обработку кода, выход и сохранение прежнего OTP-входа. Выполнить существующие тесты аккаунта и журнала.

Владелец проверяет тестовый HTTPS-сайт на компьютере и телефоне: подтверждение и отмену Telegram, повторный вход в тот же аккаунт, сохранение после обновления страницы, добавление и удаление на двух устройствах. Проверить возврат в исходный браузер, особенно при переходе в приложение Telegram.

Импортировать JSON вручную в нужный аккаунт и сравнить итоговые часы, задания, заходы и посадки. Повторный импорт с добавлением может создать дубликаты. Проверить также работу калькулятора без входа и раздельность журналов разных аккаунтов.

## 5. Публикация

После успешных проверок подготовить обычную папку файлов и PR с описанием изменений. Настройки Telegram для основного проекта выполняются отдельным шагом: тестовые ключи не переносятся вместе с файлами. Налёт импортируется владельцем после первого рабочего входа Telegram. Почтовый способ входа сохраняется.

На этом этапе не добавляем команды бота, рассылку, Telegram Mini App или автоматическое объединение аккаунтов: они не нужны для кнопки входа.
