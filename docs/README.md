# Руководство проекта

Актуализировано 11 октября 2026 года после переноса полезных материалов из полной локальной резервной копии.

Основной сайт: [moonhaze.ru](https://moonhaze.ru). Проверка изменений: [dev.moonhaze.ru](https://dev.moonhaze.ru).

## Как работает калькулятор

`index.html` — основной калькулятор: время заданий, суммарный налёт, десятичные часы, заходы и посадки. Без входа журнал хранится в браузере; после входа по коду из письма используется журнал аккаунта в Supabase. Эти два списка не объединяются автоматически. Перенос записей выполняется через экспорт и импорт JSON. `local.html` сохраняет прежний локальный калькулятор, `registration.html` отвечает за вход.

Тестовый и основной сайты используют **одну базу Supabase** по решению владельца. Изменение облачного журнала в одном аккаунте видно на обоих сайтах. Гостевые записи принадлежат адресу и браузеру: на основном сайте сохраняется ключ прежней версии `flight-time-entries-v2`, при сборке для `dev` используется `flight-time-test-guest-v1`. Вход не переносит гостевые записи в аккаунт.

Облачное сохранение проверяет ревизию журнала. При конфликте с другим устройством запись блокируется до обновления списка; повтор запроса после потери ответа сверяется по идентификатору операции. Подробности реализации находятся в `cloud-store.js`, а восстановленные исходные материалы базы — в [sql/README.md](../sql/README.md). SQL не запускается при сборке или публикации сайта.

## Разработка и публикация

Разработка ведётся только в `dev`. После отправки изменений на GitHub автоматизация выполняет проверки, собирает сайт и обновляет тестовый адрес. Владелец сам выполняет merge в `main`; после этого обновляется основной адрес.

- [Работа через Git](../GIT_WORKFLOW.md) — рабочая папка, коммиты и отправка в `dev`.
- [Публикация](../DEPLOYMENT.md) — проверки, выпуски и возврат предыдущей версии.
- [Настройка Ubuntu/Nginx](../SERVER_DEPLOY_SETUP.md) — установка механизма публикации; это инструкция первоначальной настройки, её не нужно повторять для каждого обновления.
- [Правила работы](../AGENTS.md) — ветки, самостоятельный merge владельца и общая база.

В репозитории находятся исходники; сборщик `scripts/build-deploy-site.py` выбирает публичные файлы, переносит SDK в `vendor/` и создаёт `release.json`. Тесты, SQL, документация и шаблон письма в сайт не включаются.

## Локальные проверки

Из корня проекта, с установленными Node.js и Python 3:

```sh
node --test tests/auth.test.cjs tests/cloud.test.cjs
python3 -m unittest discover -s tests -p 'test_deploy.py' -v
python3 scripts/build-deploy-site.py --environment dev --output dist-dev
python3 scripts/build-deploy-site.py --environment production --output dist-production
```

28 проверок JavaScript охватывают вход по коду, повторную отправку, ошибки, сохранение локального журнала, импорт, выход из аккаунта, конфликты и сбои синхронизации. Они используют подставные ответы и не отправляют письма или запросы в настоящую базу. Ещё 16 проверок Python проверяют упаковку, ограниченный приём выпуска и откат. Обе группы включены в GitHub Actions; это не заменяет проверку настоящей доставки почты и работы в браузере.

Для просмотра собранного тестового сайта:

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist-dev
```

Открыть `http://127.0.0.1:8080/`. Вход требует HTTP или HTTPS; открытие HTML через `file://` не подходит. Локальный сайт с текущим `auth-config.js` также подключается к общей базе после входа.
