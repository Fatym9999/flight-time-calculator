# AGENTS.md

## Общие правила

- Пользователь не программист. Объясняй изменения простым языком.
- Всю разработку, исправления и эксперименты выполняй только в ветке `dev` (прежнее имя — `test/experiments`). Перед изменениями проверяй текущую ветку.
- Каноническая рабочая копия — `/Users/roman/Documents/Codex/test/flight-time-calculator`; папки `flight-time-local-backup-*` содержат архив местных наработок и не предназначены для разработки. Текущая структура соответствует GitHub: основной калькулятор в `index.html`, прежний локальный — в `local.html`.
- Изменения отправляй через Git в `origin/dev`, выбирая только файлы текущей задачи. Перед коммитом проверяй staged diff; не используй без разбора `git add .` или `git add -A`. Порядок работы описан в `GIT_WORKFLOW.md`.
- Не изменяй ветку `main` самостоятельно.
- Все слияния веток (merge) пользователь всегда выполняет сам. Не выполняй merge и не включай автоматическое слияние.
- Публикации из `dev` предназначены для `dev.moonhaze.ru`, из `main` — для `moonhaze.ru`; настройка автоматизации не разрешает агенту менять `main`.
- По решению пользователя тестовый и основной сайты используют одну базу Supabase. Не создавай отдельную базу без его запроса; изменения облачных записей затрагивают оба сайта.
- Перед тем как пользователь будет переносить изменения в `main`, объясни, что изменено и как это проверено.
- Не удаляй существующий функционал без необходимости.
- При изменениях сначала изучи существующий код и старайся вносить минимальные изменения.
- После изменений проверь, что существующий функционал не сломан.
