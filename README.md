# Калькулятор налёта

Личный журнал для учёта полётных часов, заходов и посадок. Работает на компьютере и телефоне: без входа записи остаются в браузере, после входа доступны через аккаунт.

[Открыть калькулятор](https://moonhaze.ru/) · [Тестовый сайт](https://dev.moonhaze.ru/)

## Возможности

- Добавление заданий: часы, минуты, заходы, посадки и необязательное название.
- Подсчёт общего налёта в часах и минутах, десятичных часах и количества заданий.
- Удаление записей и очистка журнала с подтверждением.
- Вход и регистрация по одноразовому коду из письма, без пароля.
- Синхронизация журнала между устройствами после входа в один аккаунт.
- Экспорт и импорт резервной копии в формате JSON.

## Как сохраняются данные

**Без входа** записи сохраняются в `localStorage` — хранилище браузера на конкретном устройстве. Они не передаются в аккаунт. Другой браузер или телефон покажет свой локальный журнал. Очистка данных сайта удалит эти записи; в приватном режиме они могут исчезнуть после закрытия сеанса.

**После входа** загружается журнал аккаунта из Supabase. Для сохранения и синхронизации нужен интернет. Журнал проверяет обновления каждые 30 секунд и при возвращении на страницу. В разделе «Синхронизация» можно обновить его вручную.

Локальный журнал и журнал аккаунта не объединяются автоматически. После выхода снова отображаются локальные записи. На основном сайте сохранён прежний ключ `flight-time-entries-v2`, чтобы подхватить записи первой версии в том же браузере и по прежнему адресу.

Основной и тестовый сайты используют **одну базу Supabase**: облачный журнал одного аккаунта общий для обоих адресов. Записи без входа хранятся отдельно для каждого адреса; сборка `dev` использует ключ `flight-time-test-guest-v1`. При переходе с прежнего адреса GitHub Pages локальные записи переносятся через экспорт и импорт JSON.

При ошибке сохранения введённые поля остаются на открытой странице. Проверьте журнал до повторной отправки и не закрывайте страницу: облачных черновиков для работы без интернета пока нет.

## Резервная копия и перенос

1. Откройте раздел «Копия данных» и экспортируйте журнал. Сохраните JSON отдельно от сайта.
2. На другом устройстве или после входа импортируйте копию в нужный журнал.
3. Выберите добавление записей или замену списка. Замена требует подтверждения; повторное добавление той же копии может создать дубликаты.

## Локальный запуск

Из корня проекта подготовьте тестовую сборку и запустите локальный сервер (нужен Python 3). Каталог `dist-dev` должен отсутствовать или быть пустым:

```sh
python3 scripts/build-deploy-site.py --environment dev --output dist-dev
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist-dev
```

Откройте `http://127.0.0.1:8080/`. В исходниках и сборке основной калькулятор находится в `index.html`, вход — в `registration.html`, прежний локальный калькулятор — в `local.html`. Для входа используйте HTTP или HTTPS, а не открытие файла через `file://`. После входа локальная сборка также обращается к общей базе.

Проверки из корня проекта (Node.js и Python 3):

```sh
node --test tests/auth.test.cjs tests/cloud.test.cjs
python3 -m unittest discover -s tests -p 'test_deploy.py' -v
```

28 тестов JavaScript проверяют вход и журналы с подставными ответами сервера; 16 тестов Python проверяют упаковку и механизм публикации. Они не отправляют письма и не меняют настоящую базу. Обе группы запускаются в GitHub Actions перед публикацией.

## Технологии и разработка

HTML, CSS и JavaScript без сборки JavaScript-бандлов; сайт размещён на Ubuntu/Nginx. Python-скрипт подготавливает публичные файлы, GitHub Actions проверяет и публикует выпуск на сервере. Для аккаунтов и журналов используются Supabase Auth и PostgreSQL, для писем — Resend. Доступ к облачным записям ограничен владельцем через политики базы данных.

В `auth-config.js` размещаются только адрес Supabase и публичный ключ. Секретные ключи базы и SMTP в файлы сайта не добавляются. Отправитель, SMTP и шаблоны писем настраиваются в Supabase и Resend; публикация сайта их не меняет. В репозитории сохранён [исходник шаблона письма](email-templates/README.md).

Разработка и эксперименты выполняются в `dev`. Отправка изменений в эту ветку запускает проверки и обновление `dev.moonhaze.ru`. Владелец сам выполняет merge pull request из `dev` в `main`, после чего обновляется `moonhaze.ru`. История Git сохраняет предыдущие версии кода; резервные копии налёта нужно хранить отдельно.
