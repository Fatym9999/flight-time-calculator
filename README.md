# Калькулятор налёта

Личный журнал для учёта полётных часов, заходов и посадок. Работает на компьютере и телефоне: без входа записи остаются в браузере, после входа доступны через аккаунт.

[Открыть калькулятор](https://fatym9999.github.io/flight-time-calculator/)

## Возможности

- Добавление заданий: часы, минуты, заходы, посадки и необязательное название.
- Подсчёт общего налёта в часах и минутах, десятичных часах и количества заданий.
- Удаление записей и очистка журнала с подтверждением.
- Вход и регистрация по одноразовому коду из письма, без пароля.
- Синхронизация журнала между устройствами после входа в один аккаунт.
- Экспорт и импорт резервной копии в формате JSON.

## Как сохраняются данные

**Без входа** записи сохраняются в `localStorage` — хранилище браузера на конкретном устройстве. Они не передаются в аккаунт. Другой браузер или телефон покажет свой локальный журнал. Очистка данных сайта удалит эти записи; в приватном режиме они могут исчезнуть после закрытия сеанса.

**После входа** загружается журнал аккаунта из Supabase. Для сохранения и синхронизации нужен интернет. Журнал проверяет обновления каждые 30 секунд и при возвращении на страницу. В разделе «Синхронизация» можно обновить его вручную.

Локальный журнал и журнал аккаунта не объединяются автоматически. После выхода снова отображаются локальные записи. На основном сайте сохранён прежний ключ `flight-time-entries-v2`, чтобы подхватить записи первой версии в том же браузере и по прежнему адресу.

При ошибке сохранения введённые поля остаются на открытой странице. Проверьте журнал до повторной отправки и не закрывайте страницу: облачных черновиков для работы без интернета пока нет.

## Резервная копия и перенос

1. Откройте раздел «Копия данных» и экспортируйте журнал. Сохраните JSON отдельно от сайта.
2. На другом устройстве или после входа импортируйте копию в нужный журнал.
3. Выберите добавление записей или замену списка. Замена требует подтверждения; повторное добавление той же копии может создать дубликаты.

## Локальный запуск

В папке проекта выполните:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8080/`. В опубликованном комплекте единый калькулятор находится в `index.html`, вход — в `registration.html`, прежний локальный калькулятор — в `local.html`. В исходной рабочей копии тестовый единый калькулятор находится в `cloud.html`. Для входа используйте HTTP или HTTPS, а не открытие файла через `file://`.

В рабочей копии с каталогом `tests/` проверки запускаются так:

```sh
node --test tests/auth.test.cjs tests/cloud.test.cjs
```

Они используют подменённый сервер и не отправляют письма.

## Технологии и разработка

HTML, CSS и JavaScript без сборщика; GitHub Pages для сайта, Supabase Auth и PostgreSQL для аккаунтов и журналов, Resend для писем. Доступ к облачным записям ограничен владельцем через политики базы данных.

В `auth-config.js` размещаются только адрес Supabase и публичный ключ. Секретные ключи базы и SMTP в файлы сайта не добавляются. Текущая почтовая настройка предназначена для входа владельца; для регистрации других пользователей нужно настроить подтверждённый домен отправителя.

Эксперименты выполняются в `test/experiments`. Изменения в `main` переносятся через pull request после проверки и подтверждения владельца. История Git сохраняет предыдущие версии кода; резервные копии налёта нужно хранить отдельно.
